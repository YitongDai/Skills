# Regional Impact Consulting

This skill captures a repeatable approach for a specific kind of short engagement: a small team (often students or junior analysts on a placement) is asked to build a defensible **economic and social evidence base** for how an organisation contributes to a region, usually to support advocacy, funding renewal, or strategic planning — and to deliver it to a real client stakeholder (a CEO, board, or sponsor) under a tight timeline.

It draws on lessons learned the hard way during one such engagement: mislabeled data, missing multiplier ratios, funding-cliff-shaped gaps in the evidence, and the everyday friction of coordinating a small team against a fixed deliverable date. All organisation names, regions, people, and figures below are illustrative placeholders — replace them with the real ones for your engagement, but keep the *reasoning*.

## How to use this skill

This is a three-part skill. Read the reference file(s) that match what the user is actually doing right now — don't load all three unless the task genuinely spans all of them.

1. **`references/economic-impact-methodology.md`** — read this when the task involves pulling, integrating, or benchmarking regional economic data (REMPLAN, ABS Input-Output tables, employment/output multipliers, GRP per capita, sector comparisons, funding trend analysis).
2. **`references/advocacy-evidence-synthesis.md`** — read this when the task involves building a case study, identifying evidence gaps, reconciling a project brief against actual data, or drafting a data roadmap / recommendations for an advocacy-facing deliverable.
3. **`references/consulting-workplace-skills.md`** — read this when the user's question is really about *how to run the engagement*: team coordination, client communication, scope decisions, presentation prep, or framing the experience afterwards (e.g. for a CV or interview).

## Core principles that apply across all three

**Defensibility beats sophistication.** When choosing between a data source the client's own stakeholders already trust (e.g. a platform their council also uses and publishes) and a more "rigorous" but unfamiliar method (e.g. self-derived national input-output estimates), default to the trusted source and use the rigorous method only to fill genuine gaps — clearly labelled as an approximation. A number the audience believes is worth more than a number that's technically superior but unfamiliar.

**Totals are not ratios.** Public economic data sources frequently mix up "total output/value-added in $" with "multiplier ratio" — these are not the same thing and mixing them up quietly corrupts every downstream calculation. Any time a figure is imported from an external source, explicitly check and label which of the two it is before using it.

**A gap in the evidence is itself a finding.** If the brief assumes a data relationship exists (e.g. "local government funds this activity") and the underlying records don't support it, don't paper over the discrepancy — surface it as a finding, worded carefully, rather than silently dropping it or silently "fixing" the brief to match reality.

**Decide and move on.** In a time-boxed engagement, deferring a genuinely secondary question (a definitional nuance, an out-of-scope data source) is a legitimate project management move — but only if it's explicitly logged as deferred, not just quietly dropped. Revisit only when it's flagged again, not proactively.

**Iterate on a locked version rather than rewriting.** Once a draft section, template, or figure is approved, treat it as locked and build the next iteration on top of it rather than reopening it — unless the user explicitly reopens that section.
